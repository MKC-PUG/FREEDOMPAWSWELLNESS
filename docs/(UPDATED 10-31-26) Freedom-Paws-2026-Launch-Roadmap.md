## What holds public mode

Public mode is the Vercel setting `NEXT_PUBLIC_SITE_MODE=public`. It allows search indexing and removes the preview banner. Preview mode, which is on today, disallows all robots and shows “Private preview — not indexed.”

Counsel is no longer what holds that switch. The October 26 note says selling, public mode, and the shop wait for the founder’s notice that the EIN is opened and the bank account is open. That notice has not been given.

Besides the EIN and the bank, public mode waits on these:

1. A **$1 Stripe charge that lands in the Freedom Paws Wellness LLC account.** Week 3 of the twelve-week plan. A test charge must not hit a personal account.
2. A **membership or one protocol unlock that works on a second device.** Same week as the $1 charge, and it is the pass before week 4’s site-mode flip.
3. A **Framer CTA audit** in that same week. Every button lands on a free preview job: watch, share, waitlist, booth, ViT, or enroll. No shop button and no affiliate link.
4. The **founder notice** that the EIN and the bank are actually open. The clerk note does not open public mode by itself.
5. The **iPhone server photo upload**, if a public invite includes ViT. On October 31, 2026, Direct Upload and `/vit-upload.html` completed the upload and then could not load the photo, because Vercel temporary storage is not shared across instances. The dashed-box upload that reads the file in the browser worked for the phone check. A public ViT invite will hit the server-upload error until that path is fixed.

Do not flip the switch on the day the bank login arrives. Flip it after the $1 is in the LLC and the second-device unlock works.

## Later notice — veterinarian visit link

Open this when you are ready to finish step 3A.6. Do the SQL first, then the app check. The programming is already on production. Nothing else needs a push.

**Part A — SQL, once**

1. Open [https://supabase.com/dashboard](https://supabase.com/dashboard) and sign in.
2. Open the project **freedom-paws-id**.
3. In the left sidebar, click **SQL Editor**.
4. Click **New query**.
5. Paste this whole script.

```sql
alter table public.pet_vault_entries drop constraint if exists pet_vault_entries_kind_check;

alter table public.pet_vault_entries
  add constraint pet_vault_entries_kind_check
  check (kind in ('vet_record', 'vaccination', 'daily_note', 'gait_clip'));

alter table public.pet_vault_entries
  add column if not exists storage_path text;

insert into storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
values (
  'pet-vault-media',
  'pet-vault-media',
  false,
  26214400,
  array['video/mp4', 'video/quicktime', 'video/webm']
)
on conflict (id) do update
set
  public = false,
  file_size_limit = excluded.file_size_limit,
  allowed_mime_types = excluded.allowed_mime_types;

create table if not exists public.pet_vault_shares (
  token text primary key,
  pet_id uuid not null references public.pets(id) on delete cascade,
  owner_id uuid not null references auth.users(id) on delete cascade,
  expires_at timestamptz not null,
  created_at timestamptz not null default now()
);

alter table public.pet_vault_shares enable row level security;
```

6. Click **Run**.
7. The result should say **Success** with no red error. Run it once. If the bucket lines are the only error, delete those lines, run the rest, then in the left sidebar open **Storage**, choose **New bucket**, name it `pet-vault-media`, leave it private, and set the file limit to 25 MB.

**Part B — app check**

1. Open [https://app.freedompawsinc.com](https://app.freedompawsinc.com).
2. Sign in with the owner account.
3. Open **My Pets** and open one dog. Add one picture and one short note on the vault if that dog does not have them yet.
4. Save a short walking video on that dog.
5. Tap **Create veterinarian link**.
6. Tap **Copy link**.
7. Open a private window, paste the link, and leave the owner signed out of that window.
8. Pass when the page shows the notes, the pictures, and the walking video. A PDF saved as a file name only shows the name.

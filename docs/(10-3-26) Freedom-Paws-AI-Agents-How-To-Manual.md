## 1. Commentary — what “using agents” actually means here

An AI agent in Cursor is not an employee and not a department head. It is a **fast specialist that reads files and drafts work**. You remain:

- The **orchestrator** (what gets done this week)
- The **compliance officer** (what must never be claimed)
- The **publisher** (what goes live)
- The **operator** (shelter calls, payments, counsel email)

If you treat agents as a staff of twenty that can “run the company,” you will get overlapping edits, invented metrics, and legal copy that contradicts Bass. If you treat them as **named roles with one job per chat**, they compound your hours without replacing judgment.

**Rule of one:** one chat = one agent name = one outcome = one file set. When the outcome is done, close the chat. Start a new chat for the next job, even if you use the same agent name.

### Daily loop (keep it this short)

1. Name the agent out loud in the first line of the prompt.  
2. Point at files with `@` or a path.  
3. State L5 status: **open** or **cleared on [date]**.  
4. List Do / Do not / Done when.  
5. Read the output. If it touched the wrong files, stop and revert.  
6. You take the human action (email, Framer publish, social post, bank).

### When to use **one** agent vs **several**

| Use one agent | Use several in parallel | Never parallel |
|---------------|-------------------------|----------------|
| One bug in `/diagnostics` | SuperBud scripts **and** a books-log update | Two chats editing `lib/legal/content.ts` |
| One email draft to Paula | Framer CTA list **and** a shelter HOLD draft | Two chats in the same page.tsx |
| One checklist update | QA click-path **and** caption calendar | Engineer + counsel clerk both “fixing” Terms |

**Hand-off sentence (paste between chats):**

> Prior agent: **[NAME]** finished **[X]**. Do not redo X. You are **[NAME]**. Your only job is **[Y]**. Read these files first: **[paths]**. L5 is **[open / cleared DATE]**.

### When to **change** agents (switch the name, usually a new chat)

| Signal | Switch from → to | Why |
|--------|------------------|-----|
| The chat starts mixing code, legal, and marketing | Any → **ORION** to re-split the work | Context pollution |
| The engineer is writing shelter emails | FORGE → **NEST** | Wrong job |
| Counsel text is about to be pasted into the app | LEX → **FORGE** (implement only approved text) | Clerk drafts; engineer ships |
| SuperBud script includes shop CTAs before L5 | BUD → stop; **LEX** if claim language | Compliance |
| You need “is this clickable on iPhone?” | FORGE → **PROOF** | Build vs verify |
| Revenue, Stripe, membership copy | FORGE or ECHO → **PAY** (after L5) | Money surface |
| Clinic / DVM language leaking into consumer ViT | Any → **VITRIX** for B2B only; FORGE to **remove** clinic words from `/diagnostics` | Two products, two voices |
| The same chat is longer than ~15 back-and-forths on unrelated tasks | New chat, same agent name | Long threads invent facts |
| Model-provider / overload errors | New chat; attach files, do not paste the whole company history | Size, not your wording |
| You disagree with strategy, not a file edit | **ORION** or **ATLAS** | Do not let FORGE rewrite the business model inside a bugfix |

### Important factors (do these even when you are in a hurry)

- **L5 is a kill switch.** Until Bass written clearance: no public mode, no EIN, no company bank, no scaled Email 1, no “shop now,” no hard 10% give-back, no reunion-rate claims.  
- **Agents do not contact owners** on a biometric match. Human review stays human.  
- **Agents do not diagnose.** ViT is educational. VitProScan is a later B2B line with separate terms.  
- **Do not train on secrets.** Never paste EIN, bank numbers, passwords, or full ID scans into a prompt.  
- **One writer per file.** Git will not save you from two agents rewriting the same Terms page.  
- **Precision beats politeness.** “Fix diagnostics” is a bad prompt. “Change only the red banner copy in `app/diagnostics/ViTResultsPanel.tsx` to Bass wording; do not change protocol ranking” is a good prompt.  
- **Done when** must be checkable on a phone or in a file. “Make it better” is not done.
